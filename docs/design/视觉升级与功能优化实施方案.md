更新日期：2026-09-30。第一轮代码已完成并通过本地验证，尚未部署。

同日追加：已完成公开照片显示修复、编辑个体内的照片管理，以及用户 HEIC 原片的首页特写。具体见第 9 节；其中 ADM-07 的基础图库入口已经落地，逐张控制公开范围仍属于后续任务。

## 2. 设计方向与素材规范

### 2.1 参考站中实际借鉴的部分

- [灰质首页](https://graymatterreptile.com/en)：真实照片与浅色说明板块交替，照片停驻后被文字板块覆盖。
- [基因介绍](https://graymatterreptile.com/en/pages/gene-list)：图像帮助理解专业内容，图形风格保持一致。
- [联系页](https://graymatterreptile.com/en/pages/contact)：场景插画让品牌有具体的生活空间。
- [活动页](https://graymatterreptile.com/en/pages/festival)：像素动画承担局部叙事。该参考站使用视频，不能把它与静态像素插画混为一谈。
- [商品目录](https://graymatterreptile.com/en/collections/all)：统一拍摄背景、画幅与信息层级，照片优先于装饰。

本项目使用自己的代码和用户提供的照片，没有使用灰质的照片、人物、标志或动画素材。

### 2.2 本项目的视觉约定

| 元素 | 约定 |
| --- | --- |
| 主色 | 森林绿与米白；浅橄榄绿作为强调色，销售/告警颜色另有明确文字 |
| 摄影 | 展示真实动物与真实环境；网页压缩与裁切不改变动物的颜色和基因表现 |
| 线稿 | 首页主视觉和品牌图形共用自然、克制的描线方向；猪鼻蛇保持上翘吻部特征 |
| 像素画 | 用在收尾、空状态或独立知识场景，控制面积；工作表单不持续播放大动画 |
| 文案 | 中文为主，英文用于小标题；不以未经核实的统计、健康或遗传承诺充当装饰 |
| 动效 | 内容首先可见；按视口启停，减少动态效果时静态；不要求等待动画结束才能操作 |
| 前后台差异 | 公开页面强调图片与故事；内部页面强调识别个体、日期、状态与操作效率 |

`DESIGN.md` 是较早的外部设计分析资料。本轮及后续自然主题的视觉决策以本文与实际页面为准，不强行套用其中的 Apple 蓝色主题。

### 2.3 已有照片如何使用

来源：用户提供的 `fd69d85213bfdae08245032edeffd04c.jpg`，约 7.4 MB。

- 发布的是 `assets/photos/breeding-room-800.webp` 和 `breeding-room-1600.webp`。
- 仅做方向归一、尺寸适配和编码压缩，没有删除现场物品、修改环境或生成替代爬房。
- 页面以 CSS 适配不同画幅，桌面优先展现环境全貌，手机保留主要饲养架。
- 原始 JPG 留在工作区；构建白名单不把根目录原图发布到网站。
- 这是固定的品牌图片，随网站部署发布；它不是某条个体的照片，不需要写入 Supabase 个体媒体表。
- 个体照片继续沿用私有 Supabase Storage、公开发布校验及媒体函数的既有逻辑。

### 2.4 后续需要补充的素材

| 素材 | 建议数量/规格 | 用途 | 验收条件 |
| --- | --- | --- | --- |
| 猪鼻蛇头部与盘身近照 | 2–3 张原片，主体清晰，长边建议至少 1600 px | 第二幅照片段落、修正线稿的吻部比例 | 确认使用授权；不标成未对应的出售个体 |

| 日常照料细节 | 2–3 张，标签/称重/记录等 | 品牌内容与知识封面 | 不展示私人联系方式或其他人的资料 |
| 品牌介绍 | 约 100–180 字 | 独立品牌介绍或扩展理念区 | 繁育方向和经历由实际情况确认 |
| 对外联系与交付说明 | 一个正式联系入口和明确条款 | 咨询引导、购买指南 | 不自行编造配送、保证和退款承诺 |
| 原创像素角色 | 待确认角色后制作 | 知识场景、空状态 | 猪鼻蛇特征清楚；与本站配色一致；附静态版本 |

这些素材的缺失不影响本轮页面使用，后续接入真实内容时再扩大照片段落。

## 3. 下一轮：公开网站与品牌内容

以下保留原任务定义；最新交付状态以第 11 节为准。P1 为优先，P2 为其后，P3 为独立规划项。

### PUB-01 · 真实个体照片标准化（P1）

**改动：** 后台照片管理明确封面与排序；公开卡片统一比例，详情尽量完整展示动物；上传前后区分原图与显示缩略图。

**依赖：** 真实个体照片、当前媒体归属和权限规则。若新增封面焦点字段，需要单独迁移。

**验收：** 同一照片不能串到其他个体；封面调整即时反映在对应公开档案；竖图不拉伸；加载失败仍可切换其他照片；未发布照片无法通过公开链接访问。

### PUB-02 · 个体详情的档案式排版（P1）

**改动：** 桌面大图加右侧资料，手机图片优先；固定性别、出生日期、编号、状态的顺序；基因摘要与成长信息分区；长标题合理换行；缩略图支持明确的当前状态与键盘操作。

**依赖：** 现有公开字段投影，不能直接读取私有个体表。

**验收：** 公开字段没有成本、内部备注或联系方式；可能携带与确定携带清楚区分；留种/已售不出现可提交购买意向的错误入口；预留仅接受候补咨询。

### PUB-03 · 目录筛选与返回现场（P1）

**改动：** 现有搜索/系列/性别/状态/排序整理成桌面筛选栏和手机筛选面板；显示已选条件、结果数与清空入口。后续加入出生年份及结构化基因条件。

**依赖：** 年份/基因条件需要同步调整目录接口、分页计数与索引。

**验收：** 刷新和分享保留条件；详情返回目录保留滚动位置；空结果可以一键清空；清空不留下旧分页；总数来自匹配数据而非已加载卡片数。

### PUB-04 · 首页精选与第二幅实拍（P1，素材就绪后）

**改动：** 用已发布个体充实精选区；增加猪鼻蛇近照与简短介绍的过渡。最多增加一个照片章节，控制总页长。

**依赖：** PUB-01 的真实照片和明确精选顺序。

**验收：** 下架个体从精选中同步消失；无数据仍显示诚实的空状态；手机能快速到达个体列表；不把爬房照片代作个体封面。

### PUB-05 · 图文知识入口（P2）

**改动：** 建立饲养、基因、繁育三类入口；封面与简短摘要进入文章；文章支持标题目录、图片说明、更新时间和相关内容。

**依赖：** 可发布的原创或获授权文章；需先确定静态文件或数据库内容管理方式。

**验收：** 没有空链接或示例文章冒充正式内容；专业信息有来源与适用范围；手机长文行宽、字号和图表可读。

### PUB-06 · 原创像素繁育室（P2）

**改动：** 在当前的小蛇探头动作基础上，制作一个独立像素场景及少量动作，如看记录、蛇探头、孵化盒打开。优先用在知识入口或活动页。

**依赖：** 角色和场景草图确认、原始动画资产。第一轮的登录场景是描线 SVG，并非完整像素人物动画。

**验收：** 同时只出现一个主要场景；有静态封面；手机首屏不下载大视频；不可遮挡按钮；减少动态效果时不自动播放；素材许可与源文件可追溯。

### PUB-07 · 品牌与购买说明完善（P2）

**改动：** 增加确认后的品牌文字、联系入口、咨询反馈时段和交付说明；整理 FAQ 的顺序。

**依赖：** 真实联系方式与实际服务约定。

**验收：** 提交意向、预留、收款、交付的含义一致；页面不出现“已支付”但系统仅记录意向的情况；不复制参考站的跨境服务承诺。

## 4. 下一轮：内部工作台

### ADM-01 · 种群库与繁育个体的识别效率（P1）

**现状：** 已有独立入口；留存后在种群展示，繁育栏原记录保留并标记；上架复用原个体，另有销售状态。

**改动：** 卡片加入私有封面、最近记录和清楚的状态分组；提供列表/卡片切换；分开显示“库归属”“留存”“生命周期”“销售状态”。

**验收：** 留存不产生第二个个体身份；成长资料、照片、亲本不丢失；已留存幼体不重复统计；取消出售恢复正常销售标识，而不是改写生命周期。

### ADM-02 · 繁育库按窝次分组与批量登记（P1）

**改动：** 按年份/窝次分组；一窝展示亲本、出壳日期、登记数量和未登记数量。批量登记前预览编号，各条单独确认性别与基因。

**依赖：** 批量登记事务或可重试的逐条接口；现有实际孵化数限制。

**验收：** 编号冲突显示到具体行；重复提交不重复生成；失败行可重试；登记数量不超过实际孵化数；未知性别与基因保持未知。

### ADM-03 · 成长时间轴与留种评估（P1）

**改动：** 喂食、蜕皮、体重、健康观察按日期归档；体重趋势来自实际记录；留存前可写育种目标、观察结果与理由。

**依赖：** 盘点已有记录字段，缺失的评估字段再加迁移。

**验收：** 修改/删除记录有明确权限与反馈；缺记录不自动判定异常；留种理由可回看；AI 只给建议，不自动留存或判定健康。

### ADM-04 · 繁育计划与实际进度（P1）

**现状：** 已有手动计划、实际交配结果、产蛋/出壳记录、登录后首页临近提醒。

**改动：** 增加按阶段与月份查看；同一计划多窝进度单独呈现；待办可直接打开相应记录表单。

**验收：** 预计日期与实际日期不混写；交配不成功后不继续错误提醒预计产蛋；多窝不被第一窝的出壳状态覆盖；当天不再提醒仅影响弹窗，不能丢失待办入口。

### ADM-05 · 公开展示与销售操作层级（P1）

**改动：** 公开展示列表提供照片缩略图、缺失资料提示和清楚的发布状态；编辑、预览为常用操作，删除单独放置；上架前可检查将公开的字段。

**验收：** 删除公开档案不删除内部个体；预留和收款中的个体不能绕过销售流程直接取消；待出售标签随真实发布状态更新；不能仅为看封面而强制上架。

### ADM-06 · 数据分页与统计准确性（P1）

**改动：** 大型种群、繁育、公开展示、记录列表分域分页；总数和统计独立查询；筛选作用于全量匹配数据。

**依赖：** 查询接口、索引和权限验证；不能只在前端切分已有的最近 300 行。

**验收：** 超过加载上限仍可查到旧记录；更换筛选回到第一页；汇总数与权限范围一致；现有完整支出台账读取不退化。

### ADM-07 · 个体照片独立管理（P1）

**改动：** 从个体档案直接管理照片、封面与说明；区分内部照片和选入公开档案的照片。

**依赖：** 复用现有私有 Storage 与媒体归属，补充明确的公开选择机制。

**验收：** 未上架的种群仍可管理照片；只公开选中的照片；删除前展示用途；失败可重试；不产生引用已经删除文件的封面。

### ADM-08 · 配对实验室与 AI 对话（P2）

**改动：** 父本、母本和预测结果按区域组织；保留基因不确定性；AI 操作固定位置，长回复增加段落与来源入口，生成中状态不遮挡阅读。

**验收：** 蓝底/深底按钮文字对比度至少 4.5:1；阅读历史时不强制跳底；可返回最新；失败可重试；建议不能直接改写基因事实。

### ADM-09 · 手机导航、筛选和表单（P2）

**改动：** 导航按概览、个体、繁育、经营、更多分组；保留种群与繁育个体的清楚入口；常用筛选可保存；长表单固定操作区。

**验收：** 360 px 宽度没有页面级横向溢出；主要触控目标至少 44 px；软键盘打开后能看到当前输入；保存/取消可达；退出登录入口不丢失。

### ADM-10 · 全站异常与反馈状态（P2）

**改动：** 加载、空数据、无权限、网络失败、部分保存失败分别呈现；空状态复用手绘图形；危险操作明确作用对象。

**验收：** 不用“暂无数据”掩盖请求失败；保存中防重复提交；成功提示不挡连续操作；权限拒绝不误报保存成功；关闭弹窗后焦点回到触发按钮。

## 6. 实施顺序与交付规则

1. **第一轮（本次已完成）：** 真实爬房、滚动层次、登录场景、基础插画与小动效。
2. **第二轮：** PUB-01/02/03 + ADM-01/05/07，优先打通“照片 → 个体档案 → 公开展示”，解决最常用的识别与操作问题。
3. **第三轮：** ADM-02/03/04/06，围绕幼体登记、成长、留种、提醒和规模增长完善数据流程。

## 9. 追加交付：公开图片修复、个体照片编辑与蛇的特写

### 9.1 问题定位与修复

已使用当前 Supabase 的真实公开数据只读验证：Y005、Y007 均有照片记录，原图分别约 5.1 MB 和 4.7 MB，均为 PNG。

原图片接口存在两处问题：

1. 强制要求 `SUPABASE_SERVICE_ROLE_KEY`，但本地配置未提供该变量，因此返回 503；现有 Storage 的发布照片读取策略本来已经允许发布密钥读取这些照片。
2. 接口读取整张原图并编码为 Base64，原图体积增加约三分之一后可能超过 Netlify 6 MB 的缓冲响应上限。因此单纯补密钥并不能可靠解决这两张大图的问题。参考：[Netlify 函数限制](https://docs.netlify.com/build/functions/configuration/)。

新流程：浏览器请求本站图片接口 → 验证照片所属档案当前已发布 → 请求 Supabase 生成 60 秒签名地址 → 302 跳转，由 Storage 直接传输图片。本站不再把原图编码进函数响应。

- Storage bucket 继续私有；未发布、已删除展示档案或不存在的媒体路径不签发地址。
- 图片接口没有服务端密钥时使用发布密钥及现有 Storage 策略；配置了服务端密钥时仍先检查发布状态。
- 重定向响应不缓存，签名地址限定本站配置的 Supabase 域名、bucket 和已校验路径。
- 下架会阻止新地址签发；已签发地址最多在其 60 秒有效期内继续访问。不能把这个行为描述为已经发出的地址瞬时失效。
- 现有照片无需重新上传。本次没有修改真实数据库、Storage 文件或线上部署。
- 新增照片及替换照片自动输出最长边 1800 px 的 WebP；原始 JPEG / PNG / WebP 每张可选至 20 MB，压缩后必须小于 8 MB。
- 原有两张大 PNG 仍保留原文件；如希望进一步降低下载流量，可在后台使用“替换照片”重新处理，操作前核实个体和原片。

### 9.2 从哪里管理照片

入口一：**种群 / 繁育个体 → 完整个体档案 → 编辑个体 → 个体照片**。

入口二：**公开展示 → 对应档案 → 照片**。两处共用同一份图库。

支持：上传、预览、编辑说明、拍摄日期、设为封面、替换图片、删除图片。替换时保留原说明、日期与封面排序。

没有展示配置的个体在第一次上传时创建未发布的图库配置；打开编辑不创建数据，上传不自动上架。已发布个体的新照片会同步对外展示，界面有明确提示。新增个体需要先保存身份，再上传照片。

照片独立保存，不和个体资料形成假事务：照片按钮立即执行，底部保存/取消只处理个体资料。照片操作不会重置尚未保存的个体备注。上传时阻止重复操作和提前关闭；部分失败显示已完成数量，重试只需选择未成功的照片。

本次沿用 `specimen_listings` / `specimen_media` 的现有归属，没有新增表或 SQL。未来若需要“某张仅内部、某张公开”的逐张权限选择，仍需单独设计，不应误认为本次已经具备。
