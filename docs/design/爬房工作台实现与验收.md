## 进入与使用

后台登录后进入「爬房工作台」，或访问 `/admin#room`。沿用后台管理员、编辑者权限。

1. 在「房间设置」填写房间尺寸。首次是空房间，不生成示例蛇只或默认喂食周期。
2. 进入「搭建房间」，添加银色爬柜。配置柜体宽、深、高、朝向，以及每层高度、盒数和盒体尺寸；可贴四墙摆放，或进入现有柜点击「复制柜体结构」再调整新位置。先保存布局草稿，再「应用布局」。
3. 点击空盒安排已有蛇只；点击占用盒可移动蛇只、整盒转移、交换位置、称重和查看计划。
4. 点击高亮的「喂食计划」，按一个或多个柜设置每周固定日及各日时刻，或每 N 天一次，并填写每次老鼠只数。单格通过「本格喂食计划」独立配置、不安排喂食或恢复继承。柜级修改默认保留独立格计划。「备料批次」根据这些计划汇总鼠重和数量，不是配置频率的入口。
5. 「鼠重规则」编辑蛇重与鼠重档位。「标签」编辑带字段占位符的模板，配置行顺序、文字前缀、字号和对齐；支持房间默认、单柜覆盖及格位备注。
6. 顶部七日条选择日期；「全部日期」显示整周。总览侧栏列出各柜所需鼠重规格与只数，进入柜体后当前柜备料显示在顶部。
7. 「备料批次」可从当前范围勾选任务并锁定鼠重和数量；之后可重新打开批次继续逐项记录。
8. 点击盒子或「逐项巡柜」记录投喂、确认进食、拒食、跳过，也可对单次计划改期或取消。已记录结果可在爬房中更正。

## 已实现的核心交互

| 范围 | 当前行为 |
| --- | --- |
| 房间与柜体 | 默认立体，可拖动旋转、缩放，支持切换俯视和单柜正面；切入柜体平滑过渡，返回恢复场景视角 |
| 参数化外观 | 银色开放式架体、半透明长方形盒、层板与轮脚；每层盒数可以不同，尺寸改变同步影响比例 |
| 日期高亮 | 对应盒面变色；悬停两次明暗脉冲后常亮；整周时用分段色块及日期文字区分同格多日计划；总览小格图与柜面联动 |
| 可访问性 | 日期支持键盘聚焦，手机使用点选；减少动态效果时直接显示高亮；手机保留编号和鼠重，详细资料点击查看 |
| 位置 | 蛇只与格位、实体盒分别建模；转移前预览双方当前周排期及任务变化，可继承目标计划或携带原计划；占用格删除受保护 |
| 计划与备料 | 按房间时区生成任务，柜级继承与单格覆盖；同一蛇多次计划分别计料；未知体重、数量显示待确认 |
| 规则与批次 | 规则可保存草稿版本、预览影响、启用历史版本；已确认批次的日期、鼠重、数量和规则来源保持快照 |
| 标签模板 | 1–6 行纯文字模板，可重排字段及添加前缀，字号 10–20 px，支持房间默认、柜体覆盖、格位备注和实时预览 |
| 记录 | 实际结果与成长记录联动，重试不会重复记账；拒食与成功进食分开；批次可恢复逐项操作，实际用量偏离确认备料时须注明原因 |
| 保存 | 布局草稿可撤销、重做；数据库有版本冲突检测、权限检查、事务和重复请求保护；断线或缺迁移明确报错 |

初始规则沿用用户确认的上限分档：`(0,10]→1–2g`、`(10,23]→2–3g`、`(23,35]→3–4g`、`(35,45]→4–6g`、`(45,60]→6–8g`、`(60,120]→7–11g`、`(120,200]→16–20g`、`(200,+∞)→20–24g`。160g 和 200g 均落入 16–20g 档。页面配置支持修改、新增和删除档位，并校验空档和重叠。

## 发布步骤

1. 在已应用项目此前迁移的数据库上依次执行 [039_room_workspace.sql](../../supabase/migrations/039_room_workspace.sql)、[040_room_rules_and_batches.sql](../../supabase/migrations/040_room_rules_and_batches.sql)、[041_room_label_font_size.sql](../../supabase/migrations/041_room_label_font_size.sql)、[042_room_incubators.sql](../../supabase/migrations/042_room_incubators.sql)。已执行 041 的环境只需新增 042；041 放宽标签字号下限至 10，042 增加孵化占用与历史、批量入住及后台计划生成。本次开发未连接或修改生产数据库。
2. 运行 `npm run build`，通过项目现有 Netlify 发布流程发布静态文件及 Functions。`netlify.toml` 中 `room-plan-generate` 每 15 分钟执行；服务器须配置 `SUPABASE_URL`、`SUPABASE_PUBLISHABLE_KEY`、`SUPABASE_SERVICE_ROLE_KEY`，服务密钥不得进入前端。迁移文件不会随站点自动执行。纯静态本地预览不运行定时函数。
3. 使用实际后台编辑账号进入爬房，录入房间和柜体尺寸，分配一条现有蛇，配置计划并刷新验证持久化。
4. 用另一个客户端验证版本冲突提示，再核对成长记录中的实际喂食结果。正式数据与身份服务的这部分验收需在部署环境执行。

迁移新增房间配置、格位占用、位置历史、计划快照、实际喂食及请求幂等记录。写入经私有 RPC 完成，匿名访问不可读取爬房。由爬房生成的成长喂食记录须在爬房内更正，避免两个入口产生不同结果。

### 039 外键类型错误修复

若此前执行 039 报 `measurement_id` 的 `uuid` 与 `snake_measurements.id` 的 `bigint` 不兼容，请使用修正后的 039 重新执行，成功后再执行修正后的 040。现有成长记录主键按数据库结构说明为 `bigint identity`；爬房关联列及写入保护列已改为 `bigint`，两个迁移中的喂食函数变量改用 `snake_measurements.id%TYPE`。

完整执行 039 文件时，建表位于同一事务内，本次外键失败不会提交前面的建表操作。如果 SQL 会话仍提示事务已中止，先执行 `ROLLBACK;`，再重新执行完整文件。不要只重跑失败之后的片段。

此前数据库测试的成长记录主键错误地使用了 UUID，未覆盖实际表结构；已修正为 `bigint identity` 并复验 3 项数据库测试，覆盖 039／040 执行、实际喂食新增与更正、记录保护和批次关联。

## 本地场景性能补验

环境：Headless Edge 153.0.4234.48，合成数据，无 CPU 降速；390px 为浏览器模拟。测试独立场景，不包括生产登录、网络请求及完整工作台启动。

| 场景 | 桌面 1440×1000 | 390px 模拟 |
| --- | ---: | ---: |
| 12 柜、600 格首次渲染 | 54.0 ms | 48.7 ms |
| 两帧后交互探针 | 220.5 ms | 58.3 ms |
| 重复渲染中位数 | 22.6 ms | 26.3 ms |
| 80 格柜面渲染 | 22.1 ms | 18.9 ms |
| 50 次切换及缩放平均耗时 | 36.4 ms | 37.0 ms |

预热自动化脚本后再测两轮各 50 次切换与缩放，场景 DOM 始终 2625、CDP 事件监听器始终 39；第二轮 GC 后 JS heap 分别增加约 3.6／2.2 KiB，未发现持续线性增长。无残留交互层或脚本错误。原始记录：[room-scene-performance.json](../../artifacts/room-scene-performance.json)。

这些数据不能换算为真实设备动画帧率，也不代表生产网络首屏已达到 2 秒。设计方案 14.2 的真机帧率及生产首屏指标仍需部署后实测。

## 2026-10-14：日期备料汇总与柜体喂食模式

### 本轮行为

日期选择沿用多选：点击一天选中，再点取消；“全部日期”查看当前周。日期栏始终显示全房计划。总览右侧增加“全部柜子”备料卡，按所选日期跨柜合计各鼠重范围的只数。进入单柜后，顶部显示当前柜小计；已选日期时同时保留全房合计，避免把单柜数量误当成全房数量。

只数取每次计划配置的 quantity，不把一条蛇固定当作一只鼠。同鼠重范围合并，重复任务去重；已投喂、已进食、拒食、跳过、取消及冬化任务不重复计入待备料。缺少有效体重或只数单独提示，不按零只静默处理。无计划及冬化个体另行计数，不加入备料总数。

未确认任务使用最新有效称重和当前启用的鼠重规则，包含逾期但尚未确认的任务。排除未来日期称重，同日记录按数值 ID 倒序选择；公蛇自动建议最高为 6–8 g。已确认批次沿用确认时的鼠重与只数，并在汇总中说明；历史实际记录不改写。

单柜工具栏增加“档案模式 / 喂食模式”。喂食模式将编号、性别放在左上角，盒体中部仅显示加粗大号鼠重范围；各鼠重档底色、文字色与汇总对应。缺重显示“待称重”、空盒为中性灰。日期色继续在外框高亮并按原交互闪烁，不与鼠重底色混用；点击盒子继续进入原详情及喂食记录流程。冬化、孵蛋箱沿用各自展示，不提供普通喂食模式。

### 数据库发布与迁移

本轮新增 [048_current_weight_preparation.sql](../../supabase/migrations/048_current_weight_preparation.sql)，在已有 047 的数据库执行后部署前端。048 只替换 room_confirm_batch：确认未锁定任务时，在原权限、版本号、请求幂等和事务内，重新读取最新有效体重与当前规则，再写入批次和对应计划快照。原计划只数与日期保留，已确认／已有实际结果的任务仍拒绝重复确认；缺少有效称重整批回滚。

SQL 不会自动确认批次，不批量重写历史，也不创建新的表。未确认计划的当前重量估算属于展示计算；真正锁定时由服务端再核对，其他设备期间更新称重时以确认时的数据为准。迁移新架构时，将这段计算移到后端备料服务，并导出 room_confirm_batch 当前定义及 room_plan_snapshots、room_preparation_batches、room_preparation_items、room_rule_versions、snake_measurements 数据。
