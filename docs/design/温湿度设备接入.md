# 温湿度设备接入预留

更新：2026-10-16。两个项目采用相同的层级配置和数据格式；当前完成配置持久化、读取接口和适配器数据校验，尚未连接真实设备。

## 已确认设备与接入方向

用户已确认设备为 **达芬奇 A1 智能版，使用涂鸦集成**。这是用户提供的型号和生态信息，不等于已经完成 Home Assistant 兼容性验证。推荐后续链路：A1 → 涂鸦官方 Home Assistant 集成 → 服务端读取适配器 → 爬房层级绑定。当前仍仅预留接口。

采用该链路时，后台来源选 `home_assistant`，设备标识填写集成后的设备标识，通道填写实际测温实体 ID；若设备呈现为 climate 实体，需要在适配器中明确读取实际温度属性，不能误读目标温度。`davinci` 保留为达芬奇专用适配器占位，尚无直连实现。不要填示例中的 probe-1 作为真实数据点。

下一步在 Home Assistant 添加官方 Tuya 集成并关联设备，再核实 A1 的实际测温实体、单位及更新时间。若无温度实体，可从设备诊断的 `status`、`status_range`、`function` 核实数据点，不能按型号猜测 DP 编号或缩放倍数。湿度继续独立绑定其他传感器，不假定 A1 提供湿度数据。

## 搜索结论

以“达芬奇 加热垫”“达芬奇 温控 API”“达芬奇 涂鸦”等检索，未找到可以确认适配该爬宠加热垫的官方开放 API 或专用插件。不能把同名的视频软件、电子烟、丹佛斯温控器当作该产品。

[Home Assistant 官方 Tuya 集成](https://www.home-assistant.io/integrations/tuya/)是可选桥接方案：设备须能加入 Tuya Smart 或 Smart Life，且需要的数据点须被 SDK 暴露。仅凭“智能温控”不能确认兼容。[Tuya 官方说明](https://developer.tuya.com/en/docs/iot/Home-assistant-tuya-intergration?id=Kb0eqjig0utdd)也明确并非全部设备类别均获支持。

型号和涂鸦生态已确认；后续还需实际 Home Assistant 实体信息，或厂商提供的 API/协议与数据点定义。不需要在聊天或前端输入设备账号密码。当前未安装插件、未绑定第三方账号。

## 后台操作

爬房工作台 → **温湿度设备**。先保存房间和柜体布局，再配置每一层：温度来源、湿度来源、设备标识、数据通道/实体 ID、备注名称、数据有效期（30–86400 秒，默认 300 秒）。温度与湿度独立绑定，允许多个层共享设备与通道。选择“未绑定”并保存即可解绑。

配置关联稳定的柜体 ID 与层 ID，不依赖显示顺序。修改层高或盒子数量保留绑定；删除层一并移除绑定；复制柜体/层只复制结构，不自动绑定原设备。保存沿用布局写入的编辑权限、版本冲突检查与请求幂等机制；有未保存布局草稿时先处理草稿，避免把设备绑定到尚未保存的层。

来源选项为 davinci / home_assistant / mqtt / custom，均为待接入标记，并不意味着已实现对应协议。

## 配置与接口

持久配置在 `room_workspace.config.cabinets[].levels[].environment`：

```json
{
  "temperature": {"provider":"davinci","deviceId":"pad-01","channel":"probe-1","label":"A柜加热垫","staleAfterSeconds":300},
  "humidity": {"provider":"mqtt","deviceId":"sensor-01","channel":"humidity","label":"A柜湿度","staleAfterSeconds":600}
}
```

湿度或温度可独立省略。配置中不接受 URL、密码、令牌等额外字段。`deviceId` 与 `channel` 是不透明标识，不会被服务器当 URL 请求。加热垫探头温度不等同于盒内空气温度，备注名称应说明测量位置；实际测温值与温控目标值应使用不同通道，不能混用。

| 功能 | 旧项目 D:\hosnose | 重构 D:\hosnose-refactor |
| --- | --- | --- |
| 保存绑定 | 已有 `room_save_layout` RPC，新增 050 校验 | 已有 `POST /api/v1/room/layout`，领域模型校验扩展 |
| 读取温湿度 | `room_environment_snapshot` RPC | `GET /api/v1/room/environment` |
| 浏览器统一调用 | `SuohaRoomData.environment()` | 同左 |
| 共享格式与校验 | `js/room-environment.js` | `apps/web/js/room-environment.js`，服务端复用 |

读取要求已登录且有 editor/admin 权限。响应示例：

```json
{
  "version":1,
  "capabilities":{"read":true,"control":false,"connected":false},
  "levels":[{"cabinetId":"rack-a","levelId":"level-a",
    "temperature":{"value":null,"unit":"°C","observedAt":null,"status":"not_connected"},
    "humidity":{"value":null,"unit":"%","observedAt":null,"status":"unbound"}}]
}
```

`read:true` 表示读取接口存在，`connected:false` 表示未接通采集器。当前接口只返回 unbound / not_connected，不制造数值。没有后台轮询、数据接收端、历史库或远程温控命令。

## 后续适配器边界

厂商 API、Home Assistant 或 MQTT 网关在服务端取得数据后，将样本转换为：

```json
{"provider":"davinci","deviceId":"pad-01","channel":"probe-1","metric":"temperature","value":28.5,"unit":"°C","observedAt":"2026-10-16T02:00:00Z","status":"ok"}
```

使用 `SuohaRoomEnvironment.reading(binding, metric, sample, now)` 统一校验设备/通道身份、数值、单位、采样时间与过期状态。温度用 °C，相对湿度用 %；不接受字符串数值、未来时间或无时区时间。允许真实 0 值，缺失值用 null。协议数值校验范围为温度 -100–200 °C、湿度 0–100%，这是数据有效性边界，不是动物饲养推荐范围。超过有效期返回 stale，并保留原采样时间；离线返回 offline，不用旧数据伪装实时值。未匹配的样本返回 invalid。

实际接入时仍需实现：服务端适配器、凭证保管、网络超时与重试、去重/乱序处理、采样存储、读取接口数据合并、界面实际读数和状态展示。不要在浏览器直接读取设备或保存密钥。若未来增加设定温度/开关命令，应另立控制协议和权限，不复用此次只读接口。
