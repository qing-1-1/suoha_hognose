# 已售个体回种群库

日期：2026-10-14。本轮修复当前应用的单条 / 全部已售回库；完整销售产品改造需求另见 `D:\hosnose-refactor\docs\已售档案与上下架需求.md`。

## 原因及结果

原系统为保护销售历史，禁止直接将已售蛇改为在养，但没有提供专门的回库操作。旧已成交订单还会永久占用同一个体的销售名额，导致仅修改状态后仍无法再次完成销售。

本轮增加明确的回库事务：恢复在养、转入种群库、下架原展示、写入回库原因和快照，并为原已成交订单标记回库时间。订单仍为已成交，原收款、金额、谱系和照片保留；回库之后可重新上架、再次出售。回库不自动退款、不自动恢复旧盒位或喂食计划。

“公开展示”增加“展示管理 / 已售”标签。“已售”始终显示，包括数量为 0 的空状态；列表包含各库中的已售个体及没有公开档案的历史已售个体。可在此单条或全部回库，全部操作不受搜索限制。种群库工具栏不再放批量回库按钮；个体档案保留单条快捷入口。操作需要填写原因并确认。存在未结束交易、进行中拍卖或待核实付款时整批不执行，提示具体编号。重复提交同一次请求不会再次修改数据或增加历史。

销售列表和详情显示“已回库”，处理历史记录对应原因，避免将历史成交误读为当前仍然已售。

## 执行步骤

1. 已完成原有迁移至 045 后，在 Supabase SQL Editor 执行 [046_return_sold_animals.sql](../../supabase/migrations/046_return_sold_animals.sql)。该 SQL 只安装结构和回库流程，不自动恢复任何蛇。
2. 部署本轮前端代码，打开“公开展示 → 已售”。点击某条的“放回种群库”或“全部已售回库”，核对数量，填写实际原因并确认。
3. 完成后留在已售标签，列表和数量即时更新；全部回库后显示空状态。点击“查看种群库”查看恢复的个体。原自繁个体保留来源和父母关系，同时进入种群库。
4. 需要售卖的个体再点击“上架”，核对照片、价格和公开信息。历史订单不会阻挡新的成交。

没有新增环境变量。未执行迁移时，回库入口会提示先执行 046；不要通过关闭旧触发器或直接清空订单来绕过保护。
