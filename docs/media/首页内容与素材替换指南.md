## 1. 本轮完成的首页

首页现在按以下顺序展开：

1. 品牌首屏：保留猪鼻蛇线条艺术、主标题和探索入口；增加可暂停的爬房日常小窗口，点击进入完整场景。
2. 真实爬房：保留实拍大图与滚动文字覆盖效果。
3. 视觉入口：新增两张图片卡片，分别进入在售个体与留种展示的真实筛选目录。
4. 公开精选：继续读取管理员已发布的真实个体，支持全部、在售、留种切换。
5. 猪鼻蛇特写：保留用户原片经过特写、背景整理后的视觉。
6. 繁育理念：左侧为创始伙伴极简头像与日常手记，底部保留观察/记录/繁育/照料图标；右侧保留三个原则。
7. 繁育手记：粗像素爬房与可暂停的巡柜喂食动画、像素小剧场，以及四篇分类短文。
8. 购买指南：保留购买意向流程与常见问题。
9. 收尾与页脚：保留品牌收尾，增加繁育手记入口。

分类卡片带筛选参数；观察、记录与繁育标签更新正文及下一步入口，喂食动画有独立播放控制；四篇手记都有实际正文，支持关闭、Esc、键盘焦点返回和进入个体目录。

手机展开式导航包含个体、爬房、理念、手记、指南和工作台。保留图片轻微放大和卡片浮起；爬房采用实际 12 帧人物动作，支持暂停、重播和逐帧查看。首页小蛇首次滚入时破壳，点击打招呼。场景离开视口、页面进入后台或打开弹窗时暂停，系统减少动态效果时默认静止。旧暖光和漂浮光点不再显示。

### 换一张图片

1. 一般照片优先横向 3:2，主体不要太靠边。视觉入口会按约 1.8:1 裁切，手记封面也会裁切上下边缘；关键部分应放在中间安全区域。新版像素爬房例外，使用 2:1，封面应与动画首帧一致。
2. 导出宽度 768 和 1536 的 WebP；爬房现有规格是 800 和 1600。建议保持长宽比一致。
3. 将文件放入 `assets/photos/`，使用新的清晰文件名，方便浏览器更新缓存。
4. 修改 `images` 中对应项的 `src`、`small`、`width`、`height`、`alt` 和 `credit`；小图不是 768 宽时填写 `smallWidth`。
5. 若替换的是原有爬房或特写板块，也要同步修改 `index.html` 对应 `<picture>` 内的 `src`、`srcset`、宽高与替代文字。这两个原有板块保留静态 HTML，不会自动跟随新配置更新。
6. 只有替换成真实实拍后，才把相应的 AI / 艺术处理说明改为符合真实来源的文字。

### 改手记

每篇手记有稳定的 `id`、卡片 `title`、`description`、`image`、开篇 `intro` 和 `sections` 正文数组。标题中 `\n` 控制卡片换行，弹窗标题会去掉换行。内容按纯文本转义，不要在配置内插入 HTML。

保持当前四个 `id`（`archive`、`growth`、`connect`、`breeding`）可以直接替换全部正文；若修改它们，也需同步分类按钮与 `moments[].note` 引用。短文讲解档案、成长、繁育记录和咨询方式，不宣称未实际发生的繁育成果，不提供未经核实的诊疗方案。

### 改像素场景

`moments` 保留观察、记录、繁育三段短文：`link` 进入目录；`note` 打开手记。旧 `x`、`y` 观察点目前不显示。喂食播放器使用 4×3 帧图，每格 2:1；首屏小图与完整大图使用相同帧序。替换时同步两种尺寸帧图、静态封面、字幕和时长，详见素材制作记录。若改变帧数或排布，需要修改播放器，不能只换文件。

## 4. 后续替换优先级

| 优先级 | 内容 | 建议准备 |
| --- | --- | --- |
| 高 | 代表性个体实拍 | 至少一张完整盘身、一张吻部特写；与实际公开档案关联 |
| 高 | 真实个体照片 | 在后台给公开个体补齐封面和不同角度照片，确认已发布 |
| 中 | 品牌介绍 | 由经营者确认的名称、繁育方向和可公开的背景；不编造年限、数量或奖项 |
| 中 | 繁育手记 | 三篇真实内容可依次替换现有入门文章；照片、日期和事实由经营者确认 |
| 中 | 爬房近景 | 整理后的全景、记录本、个体观察等，避免拍入联系方式等私人信息 |
| 可选 | 专属像素角色动画 | 若希望人物实际走动或写字，需要独立角色与背景素材、逐帧动画；当前暖光与观察点已可交互 |

首页内容现已可完整浏览，不依赖上述素材才能运行。这张表用于日后换成更有品牌辨识度的真实内容。

## 5. 配置和发布

本轮是公开首页的静态内容和交互修改，不新增 SQL、不新增 Supabase 表或 Storage 桶，也不新增 Netlify 环境变量。新图片随 `assets` 打包；本轮没有执行远程发布。

本地运行 `npm run dev`，访问终端给出的首页地址。发布前运行 `npm run build`，沿用项目现有 Netlify 部署流程即可。

检查重点：桌面与手机无横向溢出；新图片可以加载；在售/留种入口筛选正确；三个场景可点选或使用方向键；手记可打开、关闭并返回触发按钮；从手记可前往目录；减少动态效果模式不播放场景动画。

本轮验证：46 项 Node 测试通过；原有 14 项浏览器用例通过；新增桌面/手机共 4 项首页浏览用例通过（修正测试定位后定向复测）。覆盖 320、390、768、1440px 宽度与减少动态效果。通过本地页面只读连接真实公开目录，读取到 2 条已公开个体，首页图片未出现加载失败。构建成功。
