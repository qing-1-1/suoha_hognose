# 视觉与功能优化记录

更新：2026-09-29。本文件记录本轮已实现与下一步建议；不代表已部署到线上。

## 繁育计划与首页提醒

- 年度计划新增直接创建入口；填写亲本、计划名称、预计交配／产蛋／出壳日期，设置提前 0–30 天提醒，默认 3 天，也可关闭。
- 计划是预计安排，不自动创建事实。实际交配单独记录日期与结果（待确认／观察到交配／成功／未成功／取消）；产蛋与出壳在关联窝次中记录。
- 计划卡片汇总每次交配和每窝进度。出壳支持开始与结束日期；每窝可单独指定预计出壳日，未指定时使用计划的预计日期。
- 提醒只出现在登录后的工作概览，包括临近、当天和逾期。按浏览器本地日历日期计算；同一浏览器同一账号可选择当天不再提醒，概览仍可手动查看。修改预计日期会成为新提醒。
- 已记录实际交配、产蛋、开始出壳的对应阶段不再提醒；关闭提醒、取消或完成的计划及待审核／退回计划不弹窗。交配未成功后不继续提示预计产蛋和出壳；已有孵化窝次仍按自身实际状态提醒。
- 一个计划的交配／产蛋预计日期代表本轮安排。多窝分别登记，各窝出壳单独判断，不用第一窝出壳替代全部孵化状态。
- 此处是站内提醒，打开页面或回到页面时更新，停留页面每分钟检查。没有微信、短信、邮件或关站后的系统推送。
- 需新增执行 `025_breeding_calendar.sql` 并部署代码；无需新增环境变量。迁移未自动应用到生产。

## 最新交互调整：繁育个体、留存与上架

本节覆盖下文此前“转库后离开自繁库”的交互说明。

- 桌面侧栏和手机导航固定提供“繁育个体”入口，直接网址为 `/admin#nursery`。
- 繁育个体栏显示自繁来源的全部个体，包括已经留存到种群的个体。
- 点击“留存”，完整档案同步显示在种群总览；本栏原记录保留并标记“已留存 · 种群同步”。底层共用同一份个体与关联资料，不产生两个相互冲突的身份，也不重复统计库存。
- 点击“上架”，打开已选中此个体的公开档案表单，默认在售并勾选发布；填写／检查资料并保存才实际发布。原繁育档案和留存标记保留，另显示销售状态。
- 公开展示每行新增“删除”。确认后从公开目录及展示列表移除，保留个体、媒体和历史意向；再次上架可恢复原配置和照片。存在有效预留、已收款或待成交交付时，先在销售流程中处理。
- 数据库新增 `024_listing_removal.sql`，在已有 `023` 后执行；已经执行过的历史 SQL 不重跑。无需新增环境变量，代码仍需要部署后线上才生效。


## 本轮已实现

- 首页保留盘旋蛇身，重画头部方向、宽颊、鼻端、眼睛和头鳞；标题分段出现，文字与蛇形有轻微指针视差，支持减少动态效果偏好。依然标为品牌艺术，不代替真实照片。
- AI 面板、结果卡片、对话入口与发送按钮统一浅色底／深色文字和深绿按钮白字；改善对话行距、移动端输入区与按钮布局。
- 后台表格改善长基因文字换行、筛选布局、焦点指示；个体编辑主要字段中文化，移动端保留退出入口。
- 种群库与自繁库分开显示。同一个体仍只有一份档案，转库不复制个体、照片、基因或谱系；转库记录保存在 `inventory_transfers`。
- 新建来源为自繁的个体，包括窝次登记的幼体，由数据库自动放入自繁库。自繁库提供窝次登记入口和历史补录入口。
- 活跃自繁个体可“选育留种 · 转入种群库”，以后也能转回。只读成员不能操作；已售、死亡或退役个体不可转库。
- 新增公开档案可从种群库或自繁库筛选。成长／配种记录的个体选项也标明库归属。
- 种群列表、自繁卡片、个体详情显示独立销售标识：已发布且在售＝待出售；预留＝已预留；成交＝已售。取消出售改成仅展示或取消发布后恢复正常销售标识，生命周期不被改成“待出售”。预留中的个体仍应通过销售流程取消，不能靠下架解除预留。
- 种群页数量和成熟分布仅统计种群库；默认种群规划与 AI 采购分析不将自繁库幼体作为现有种群资源。完整谱系仍可访问两个库。

## 本轮启用步骤

1. 在已有 `019–022` 基础上执行新增 `supabase/migrations/023_inventory_libraries.sql`，只执行一次。
2. 部署本轮代码，无需新增 Netlify 环境变量。
3. 已有档案默认留在种群库，避免把已选留的自繁种蛇自动搬走。历史自繁个体可以打开详情“转回自繁库”；若来源尚未准确记录，先核实并修改来源。
4. 新孵化个体从窝次登记，出生日期和谱系来自真实记录；手工补录旧个体不伪造窝次和亲本。
5. 库归属、生命周期、公开状态和销售状态分开管理。转入种群不会自动取消出售，也不会自动发布。

本地自动化验证与线上 Supabase 联调是两回事；本轮未执行生产迁移。

## 后续建议（尚未实现）

| 优先级 | 建议 | 具体价值与验收点 |
| --- | --- | --- |
| 高 | 自繁库按窝次分组、批量录入与编号预览 | 同窝幼体一次登记，逐条填写性别和确认基因；编号冲突与失败行清楚提示，不重复入库 |
| 高 | 进食／蜕皮／称重时间轴 | 每条幼体能回看最近进食和增重趋势，留种依据从主观印象变成记录；缺记录不判定为异常 |
| 高 | 留种评估卡 | 记录体态、进食稳定性、育种目标及人工评语，转种群前保留选择理由；AI 只能建议 |
| 高 | 大规模列表分页与独立汇总接口 | 解决原有全库读取上限及新运营列表最近 300 条限制；总数和统计不依赖已加载页数 |
| 中 | 种群与自繁卡片显示内部封面 | 直接识别个体；没有公开档案的照片也应有独立私有归属，不为显示封面而强制上架 |
| 中 | 全站筛选与空状态统一 | 基因组合条件、年龄、体重、待出售状态、同窝筛选，以及带条件的返回现场 |
| 中 | AI 对话恢复与长文本阅读 | 长回复目录、滚动位置保留、任务完成提醒；正在阅读历史消息时不强制滚到底部 |
| 中 | 移动端导航分组 | 当前横向底栏可用，但入口增多后可改为“概览／个体／繁育／经营／更多”，减少横滑 |
| 中 | 真实照片视觉规范 | 统一背景、侧面与头部角度、比例和光线；首页精选使用真实照片后再调整视觉密度 |
| 低 | 蛇形艺术的进一步细化 | 在不改变当前盘旋轮廓的前提下增加背部斑纹、自然颈部过渡；以性能与阅读为先，不加入持续干扰的吐信特效 |

不建议把在线支付、自动退款与本轮视觉调整捆绑；人工成交流程稳定后单独设计资金状态和回调幂等。


## 2026-09-30 · 需求.docx 问题修复

- 新增公开档案时展示编号、性别、出生日期、库归属、系列及照片数量；已有照片使用登录成员的短期签名地址预览。无照片时提示保存后上传，不使用示例照片。
- 窝次明确区分预计与实际出壳：预计可选未来日期；实际日期不能晚于今天，结束不能早于开始。未出壳使用「孵化中」，实际有幼体时填写已孵化数及开始日期再入库。
- 旧窝次未填已孵化数时，点击「幼体入库」进入窝次补全并聚焦数量。保存后再次入库；已登记达到总数则提示更新真实数量。数据库原有事务与数量上限保留。
- 公开详情函数兼容 Netlify 重写后的原始路径，防止正常分享链接被误判为「档案不存在」。无效标识仍返回 404。
- 公开图片先校验已发布关联，再由服务端密钥读取私有 Storage。上传与数据记录保持原逻辑。加载失败有明确提示，支持点击其他缩略图继续查看。
- 长表单内容独立滚动，保存／取消保持可见；手机表单字号与按钮触控面积加大；修改字段后清除过时错误，保存过程中防止重复提交。

部署：此次没有新增 SQL。在原有迁移已至 025 的基础上重新部署网站即可；确认 Netlify Functions 配有 SUPABASE_SERVICE_ROLE_KEY（已有购买意向使用的同一服务端密钥）。未对线上数据或部署执行写操作。

后续建议：为个体图库增加独立于公开档案的管理入口，方便尚未建立展示档案的种群直接选择真实照片；为多条幼体增加批量登记与逐条性别／基因确认，减少重复输入。

验证：44 项 Node 测试通过；10 项浏览器用例在桌面和手机尺寸下通过（包括失败后修复的定向复测）；构建与 diff 格式检查通过。浏览器使用模拟业务数据，未对真实库执行写入；Netlify 生产重写及图片配置仍需部署后验收。
